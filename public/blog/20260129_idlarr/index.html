Matrix instantiation and multiplication in IDL

January 29, 2026

I work with several people who use IDL, and over the years I’ve been asked multiple times why data sometimes appears to be transposed. Here is the reason why. I wrote this note a while ago but am posting it here in case someone else needs it. Hopefully this information becomes obsolete soon.

The row, col indices are switched when initializing arrays in IDL. For example, initializing an imat with FLTARR(288, 36) will create a 36 x 288 array (row x col) rather than a 288 x 36 array.

The “mathematically correct” way to do matrix multiplication is with the ## operator:

IDL> a = indgen(3, 2)		; 2 x 3 array, equivalent to a = [[0,1,2], [3,4,5]]
IDL> b = indgen(2, 3)		; 3 x 2 array, equivalent to b = [[0,1], [2,3], [4,5]]
IDL> a ## b
	10	13
	28	40

If a and b are transposed, then # will provide a transposed version of the above result:

IDL> transpose(a) # transpose(b)
	10	28
	13	40

Doing the latter works as long as your code is internally consistent, but it does result in transposes when importing/exporting data.
